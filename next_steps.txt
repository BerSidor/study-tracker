STUDY TRACKER — NEXT STEPS
==========================

WHY THE STUDY TRACKER IS INEFFICIENT
--------------------------------------

1. Business logic lives in natural language (CLAUDE.md), not code.
   All session management — opening, switching topics, calculating durations,
   closing — is implemented as prose instructions that Claude interprets at
   runtime. This is fragile: every behaviour depends on Claude correctly
   reading and following those instructions every single time. There is no
   source of truth you can run, test, or debug independently.

2. No tests. Zero test coverage on any session logic. If a calculation
   breaks (e.g. activeMinutes, durationHrs), there is no way to catch it
   automatically. Bugs only surface when you notice wrong numbers in the sheet.

3. Tangled concerns. "Done" conflates two separate operations: closing the
   session and syncing the Google Sheet. A failed sheet sync can leave session
   state ambiguous. These should be independent steps.

4. No seam on notifications. toast-heartbeat.ps1 is hardcoded. Swapping it
   for any other notification mechanism (Slack, widget, email) requires
   editing the script directly rather than swapping an adapter.

5. Muddled terminology. "durationHrs" appears on both sessions and segments
   but means subtly different things. "activeMinutes" only exists on segments.
   There is no authoritative glossary, which will cause bugs as features grow.


WHAT HAS TO BE IMPLEMENTED TO FIX IT
--------------------------------------

A. Extract a real SessionManager module (session.js or session.ps1)
   with a proper public interface:
     - startSession(topic, time)
     - switchTopic(topic, time)
     - pauseSession(time)
     - resumeSession(time)
     - closeSession(time) → returns a completed session object

   Claude becomes a thin orchestrator that calls these functions.
   All state-transition logic moves out of CLAUDE.md into testable code.

B. Separate sheet sync from session close.
   closeSession() writes to sessions.json. Sheet sync is a separate
   step that can fail independently without corrupting session state.

C. Introduce a Notifier interface.
   Toast, Slack, or any future channel sits behind a single adapter seam.

D. Write a domain glossary (CONTEXT.md / UBIQUITOUS_LANGUAGE.md).
   Canonical definitions for: Session, Segment, Pause, Topic,
   ActiveMinutes, DurationHrs, WeeklyGoal, DailyTarget.

E. Add tests via TDD (vertical slices, behavior through public interface).
   Start with a tracer bullet: open session → add segment → close →
   assert durationHrs and activeMinutes are correct.
